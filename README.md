# הנבחרת - אפליקציית תקבולים (PWA)

אפליקציית אינטרנט (PWA) פשוטה לרישום תקבולים על ידי משווקות שדה. עובדת אופליין,
נשמרת מקומית במכשיר ומסתנכרנת אוטומטית לגיליון Google Sheets דרך Google Apps Script.

בשלב הזה מומש רק תהליך "הוספת תקבול". "הוספת מכירה" מופיע במסך הבית ככפתור לא פעיל בלבד.

## מבנה הפרויקט

```
tikbulim-pwa/
  index.html          - כל מסכי האפליקציה
  manifest.json        - הגדרות PWA (שם, אייקונים, צבעים)
  service-worker.js    - שמירת קבצי האפליקציה לפעולה אופליין
  css/styles.css       - עיצוב
  js/config.js         - כל הערכים הניתנים לשינוי (ראו "הגדרה לפני שימוש" למטה)
  js/db.js             - שכבת IndexedDB (שמירה מקומית)
  js/api.js            - שכבת הגישה לנתונים (saveReceipt) - נקודת המעבר היחידה לשרת
  js/sync.js           - סנכרון אוטומטי לשרת
  js/tranzila.js        - אינטגרציית סליקת אשראי
  js/app.js            - זרימת המסכים
  apps-script/Code.gs   - קוד השרת (להדבקה ב-Google Apps Script)
  icons/               - אייקוני האפליקציה (הוחלפו זמנית - ראו למטה)
```

## הגדרה לפני שימוש (חובה)

כל הערכים הבאים נמצאים בקובץ [`js/config.js`](js/config.js) ויש לעדכן אותם לפני פריסה:

1. **`APPS_SCRIPT_URL`** - כתובת ה-Web App לאחר פריסת `apps-script/Code.gs` (ראו הוראות בתוך הקובץ עצמו).
2. **`OFFICE_EMAIL`** - כתובת המייל של המזכירות. יש לעדכן גם בקובץ `apps-script/Code.gs` (קבוע `OFFICE_EMAIL` בתחילת הקובץ) - שני המקומות חייבים להיות זהים.
3. **`TRANZILA_TERMINAL_URL`** - קישור מסוף הסליקה. **טרם התקבל קישור אמיתי מהחברה** - זהו Placeholder בלבד. כשיתקבל הקישור, יש לוודא מול טרנזילה את שמות פרמטרי ה-Query התומכים בהפניה חזרה (success_url_address / fail_url_address) - הלוגיקה שבונה את הקישור נמצאת ב-[`js/tranzila.js`](js/tranzila.js).
4. **`ID_NUMBER_THRESHOLD`** (ברירת מחדל 5,000 ₪) - הסף שמעליו נדרשת תעודת זהות. **טרם אומת סופית מול רואה חשבון** לפי ההנחיה המקורית - קל לשנות כאן.
5. **`CASH_CEILING`** (ברירת מחדל 6,000 ₪) - תקרת תשלום במזומן לפי חוק צמצום השימוש במזומן.

## התחברות / רישום משווקות

בניגוד להנחיה המקורית (רשימה קבועה בקוד), הוחלט לפתוח את ההתחברות באופן חופשי: בכניסה הראשונה
לאפליקציה כל משווקת מזינה בעצמה שם מלא וכתובת מייל (מסך `screen-login` ב-[`index.html`](index.html)).
הפרטים נשמרים במכשיר שלה (localStorage) ולא תצטרך להזין שוב. אין צורך לתחזק רשימה בקוד -
כל משווקת חדשה פשוט נכנסת לאפליקציה בפעם הראשונה ונרשמת בעצמה.

## אייקונים

האייקונים בתיקיית `icons/` נוצרו זמנית (רקע סגול עם האות "ה") כדי שה-PWA יהיה תקין וניתן להתקנה.
מומלץ להחליף אותם בלוגו האמיתי של הנבחרת (אותם שמות קבצים, אותם מידות: 192x192, 512x512, 512x512 maskable, 180x180).

## פריסה (Deployment)

### 1. Google Sheets + Apps Script
ראו את הוראות ההתקנה המפורטות בראש הקובץ [`apps-script/Code.gs`](apps-script/Code.gs).
בקצרה: גיליון Google Sheets חדש > הרחבות > Apps Script > הדבקת הקוד > פריסה כ-Web App
(Execute as: Me, Who has access: Anyone) > העתקת כתובת ה-URL ל-`config.js`.

### 2. GitHub Pages
1. יצירת ריפו חדש ב-GitHub והעלאת תוכן התיקייה `tikbulim-pwa/` (או שהיא עצמה הריפו).
2. Settings > Pages > Deploy from branch > בחירת הענף (למשל `main`) והתיקייה (`/root` או `/`).
3. האפליקציה תהיה זמינה בכתובת שמוצגת שם (למשל `https://<username>.github.io/<repo>/`).
4. במכשיר נייד: פתיחת הכתובת בדפדפן > תפריט > "הוספה למסך הבית" - האפליקציה תתקין כאייקון רגיל.

**חשוב:** אם ה-repo מוגש מתת-נתיב (כמו `/repo-name/` ולא משורש הדומיין), כל הנתיבים בקוד כבר יחסיים
(`./index.html`, `css/styles.css` וכו') כך שזה עובד ללא שינוי.

## עקרון "Local First" - איך זה עובד בפועל

1. בלחיצה על "אישור ושמירה" הדיווח נשמר קודם ב-IndexedDB במכשיר (`js/db.js`), עם מזהה ייחודי (UUID)
   שנוצר כבר בתחילת מילוי הטופס.
2. מיד לאחר מכן מתבצע ניסיון שליחה לשרת (`js/sync.js`). אם אין אינטרנט - הניסיון נכשל בשקט והדיווח
   נשאר במצב "pending" ב-IndexedDB (לעולם לא נמחק).
3. ניסיון סנכרון חוזר מתבצע אוטומטית בשלוש נקודות: טעינת האפליקציה, חזרה אליה מהרקע, וחזרת חיבור לאינטרנט.
4. בצד השרת (Apps Script), כל שורה מזוהה על ידי ה-UUID - שליחה כפולה של אותו דיווח מעדכנת את אותה שורה
   ולא יוצרת כפילות, ומייל נשלח רק בפעם הראשונה שהדיווח נקלט.

## נקודות שדורשות אימות/החלטה נוספת בהמשך

- **קישור טרנזילה האמיתי ופרמטרי ה-Query המדויקים** להפניה חזרה לאפליקציה לאחר סליקה.
- **סף תעודת הזהות (5,000 ₪)** טרם אושר מול רואה חשבון.
- זרימת "אשראי - לסליקה עכשיו" מבוססת על חזרה מהדפדפן כהוכחת הצלחה (ללא Webhook/IPN בצד שרת) -
  זוהי החלטה מודעת לפי ההנחיה. אם המשווקת סוגרת את הדפדפן באמצע הסליקה ולא חוזרת לאפליקציה,
  הדיווח יישאר שמור מקומית במכשיר במצב "ממתין לתוצאת סליקה" עד שתחזור לאפליקציה על אותו מכשיר.
